# v1.2.0 — Gina, preventivi PDF affidabili e builder manuale

## Corretto: il bot non dice più “non ho il tool”

- La persona usava `request_quote`, ma OpenClaw espone `secretary__request_quote`, e
  conteneva una via di fuga esplicita (“Se il tool non è disponibile…”). Il modello
  usava quella frase invece di chiamare il tool.
- L'allowlist copre ora `secretary__*` e `mcp__secretary__*`; `approval_setup.py`
  rilegge il file scritto e fallisce se un tool manca.
- `install.sh` non ingoia più l'errore di registrazione ed esegue un self-test MCP reale
  sulla copia installata.
- `doctor.py` ha il nuovo controllo `mcp_runtime`: esegue il server installato e
  verifica `tools/list` più la generazione di un PDF vero.

## Aggiunto

- **Nuovo preventivo dalla dashboard**: PDF senza modello, provider AI o WhatsApp;
  *Duplica* ricrea un preventivo con un nuovo numero.
- **Ciclo di vita**: scadenza con badge “scaduto”, ricerca, anteprima email per ogni
  preventivo, export CSV sicuro per Excel e commercialista.
- **Banner capacità**: la dashboard avvisa il titolare se il bot non vede i tool.
- **`scripts/verify.sh`**: tutta la matrice di verifica in un comando.
- **`python3 demo.py`**: demo in 60 secondi senza chiavi, WhatsApp o invii.
- Nome predefinito della segreteria: **Gina**, in dashboard, email e intestazione PDF.
- Blocco di accettazione cliente nel PDF.

## Test

158 test unitari (da 144), inclusi handshake MCP end-to-end e il nuovo flusso
preventivi. Self-test, bridge Apps Script e plugin di guardia passano su Python
3.11–3.14.

**Verificato in locale:** compilazione, 158 test, tutti i self-test, bridge, guardia
Node, generazione PDF, demo con pagina, preventivo manuale via HTTP, PDF scaricato,
CSV e anteprima email.

**Da confermare sul host:** un messaggio WhatsApp reale, un invio Gmail/Calendar reale
e `doctor.py` con `mcp_runtime: ok`.
